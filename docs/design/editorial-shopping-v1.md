# DealScout editorial shopping direction

This is the first implementation pass of the new consumer-facing visual system.

## Intent

DealScout should read as a professional shopping/deals property, not a generic SaaS landing page or AI-generated component gallery.

## Rules

- Product imagery and price hierarchy do most of the visual work.
- Serif display type is reserved for brand/editorial hierarchy; utility UI stays sans-serif.
- Avoid putting every section inside a rounded pastel card.
- Use borders, grids, alignment, and section rhythm before shadows or decorative containers.
- Keep copy short and merchandising-led.
- Homepage can feel editorial; All Deals and categories should remain dense shopping experiences.
- Existing verification, personalization, feed, admin, and distribution behavior should remain intact.

## V1 surfaces

- Global consumer header/navigation/search/footer
- Homepage hero and merchandising hierarchy
- Deal cards in grid and list views
- Shared visual tokens

Later passes should carry the same system into category pages, deal detail, saved, loading/empty states, and mobile/app surfaces.
